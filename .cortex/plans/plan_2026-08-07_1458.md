# RideNTrack - Motorcycle Group Ride Tracker

## Context
- Empty project directory — building from scratch
- **Tech Stack**: React Native (Expo) for mobile + Next.js for web dashboard
- **Backend**: Supabase (Auth, Postgres DB, Realtime channels, Row Level Security)
- **Maps**: Mapbox (route display + live markers)
- **Real-time**: Supabase Realtime channels for location broadcasting and alerts

## Architecture

```
/RideNTrack
├── mobile/          # React Native (Expo) app
├── web/             # Next.js web dashboard
├── supabase/        # Supabase migrations & config
└── shared/          # Shared types/constants
```

## Database Schema (Supabase/Postgres)

- **users** — id, username, password_hash, display_name, phone, emergency_contact, avatar_url
- **rides** — id, name, ride_code (6-char unique), admin_id (FK users), origin, destination, origin_coords, destination_coords, route_geometry, status (planned/active/completed), created_at
- **ride_participants** — id, ride_id, user_id, joined_at, is_active
- **location_updates** — id, ride_id, user_id, lat, lng, speed, heading, timestamp (for history/replay)
- **alerts** — id, ride_id, user_id, type (emergency/break/fuel/mechanical), message, lat, lng, created_at, acknowledged_at

## Key Technical Decisions
- **Ride Code**: 6-character alphanumeric (no ambiguous chars like 0/O, 1/I) for easy verbal sharing between riders
- **Location broadcast**: Supabase Realtime Presence for live locations (no DB write for every update — only periodic snapshots for history)
- **Mapbox Directions API**: Fetch route geometry between origin/destination, render as polyline
- **Expo managed workflow**: Simpler build/deploy, sufficient for location + maps
